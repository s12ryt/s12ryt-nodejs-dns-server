## 已實作模組

| 路徑 | 責任 | 依賴方向 |
| --- | --- | --- |
| `index.js` | 完整 runtime/native binding 雙 SHA 下載、候選 pending／成功promotion、失敗時previous LKG回退、SIGTERM graceful close，以及具DoH CORS的離線DNS/DoH核心。 | 只依賴Node.js標準庫；完整runtime不反向依賴bootstrap。 |
| `src/dns/` | DNS wire、SOA／Primary Zone權威語意、Zone file、DNS Policy與訂閱、自訂記錄、CNAME鏈、快取及DoH上游。 | 不依賴 HTTP 管理 UI；訂閱只經HTTPS並使用本機LKG快取。 |
| `src/services/` | UDP/TCP DNS、具 endpoint 限定 CORS/preflight 的 DoH，以及具weighted pools、health／breaker、fallback、HTTP/2、drain、Shadow、cache、壓縮與WebSocket控制的反向代理。 | 依賴 DNS 核心、route store 與 proxy cache；不依賴管理 UI。 |
| `src/admin/` | 原子設定、網域、IdentityManager、固定／自訂 RBAC、Bearer scope、API v2／OpenAPI／idempotency、防竄改審計、去敏管理 API 與靜態 UI。 | 依賴 SQLite 身分／審計／冪等儲存及抽象服務狀態；owner-only敏感權限不可委派。 |
| `src/tunnel/` | cloudflared 下載校驗、跨平台安裝、token 來源 metadata、程序生命週期與 bounded logs。 | token 明文封裝於 manager 私有欄位，經 runtime 協調更新。 |
| `src/storage/` | better-sqlite3 WAL、schema migration／guard、設定歷史、指標、Webhook、代理健康、角色／使用者／session／token、audit hash chain、idempotency及online backup。 | config仍是可攜來源；SQLite保存正式運行歷史與管理身分。 |
| `src/observability/` | Prometheus累積／區間指標、敏感JSONL日誌、Webhook HMAC持久重試及統一事件管線。 | 依賴SQLite抽象與memory EventLog，失敗不得阻斷核心服務。 |
| `src/backup/` | 敏感ZIP建立／檢查／匯入／還原／回滾，以及daily／weekly排程與保留策略。 | 依賴SQLite online backup與runtime maintenance callbacks。 |
| `src/recovery/` | startup／restore／shutdown owner-only marker、去敏復原報告與精確白名單temp cleanup。 | 不刪除config、受管備份、runtime active／pending或未知隱藏檔。 |
| `src/diagnostics/` | owner-only去敏診斷ZIP、system/runtime/schema/integrity摘要、有限events與log tails及逐檔SHA manifest。 | 重用Audit去敏；禁止讀取SQLite、完整備份、cache及認證secret。 |
| `src/benchmark/`、`scripts/benchmark.js` | deterministic資料集、真UDP／HTTP transport負載、CI／scale／release profiles、24h soak判定與owner-mode原子JSON報告。 | release profile固定100k／1000、5kQPS／1kRPS、24h且不可縮短；smoke／scale永遠非formal。 |
| `src/web/` | DNS／Zone／Policy、進階代理、可觀測、Webhook、備份、身分／角色／API token、審計鏈驗證／匯出、全自建 modal與無障礙互動。 | 只依賴管理 HTTP API；一次性secret不保存於前端state，使用內嵌SVG且無前端runtime依賴。 |
| `src/runtime.js`、`src/main.js` | 組裝共享狀態、SQLite、observability、備份／維護模式、服務與上游探測啟停、設定熱更新、proxy cache及Tunnel。 | 核心服務不受外部Tunnel、telemetry或排程單點失敗影響；還原時保留admin控制面。 |
| `scripts/build.js`、`scripts/native-bindings.js` | 打包runtime/UI/manifest，下載驗證六組Linux glibc native binding並組裝Release。 | 建置期依賴esbuild與GitHub Release；native tar採路徑、checksum、大小及重複entry防護。 |
| `Dockerfile`、`docker-compose.yml` | Debian、非root、唯讀rootfs、volume、healthcheck與graceful stop容器部署。 | 依賴Node20與`data`持久volume。 |
| `deploy/systemd/` | 專用使用者、tmpfiles/sysusers、service硬化與安裝腳本。 | Linux systemd正式部署；資料寫入`/var/lib/s12-dns-server`。 |
| `tests/unit/` | DNS chain／Zone／Policy、網域、代理 route／health／HTTP2／security／cache、設定 migration 等核心契約與錯誤路徑。 | 與直接實作同一原子變更。 |
| `tests/integration/` | 真實 UDP/TCP/HTTP/WebSocket、DoH、代理HTTP2／fallback／Shadow／drain、管理 API與runtime整合測試。 | 依賴核心及服務模組。 |
| `tests/e2e/` | 首次設密、DoH、Zone／Policy、代理進階精靈與運行控制、備份、Tunnel、鍵盤、reduced-motion及多尺寸驗收。 | 依賴完整 runtime 與 Playwright。 |
| `docs/` | 維運復原、REST API v2、Docker／systemd部署回滾與正式benchmark手冊。 | 由README導航，關鍵安全與formal驗收條款由文件測試保護。 |
| `.github/workflows/ci.yml` | Node20/22/24回歸、E2E、Docker實機health/graceful stop、非formal benchmark smoke／scale、六組native資產與tag Release。 | v1 Release需test、E2E、deployment、smoke與scale全部成功；24h formal證據獨立保存。 |
